系统架构

ccFlow 采用三层架构设计，以 Claude Code 为核心执行层，实现从代码生成到自动部署的完整链路。

PROMPT 层 — 你（指挥者）
生成主站 生成子项目 写博客 改样式 / 修 BUG 配置部署
▼
EXECUTION 层 — Claude Code
文件创建 代码写入 配置修复 构建检查 README 生成
▼
DEPLOY 层 — 自动化
git push → GitHub Vercel 自动构建 HTTPS + 全球 CDN
核心理念 主站通过 Markdown 链接指向子项目 Demo。无代码耦合、无部署依赖、互不影响。每个子项目 = 独立 GitHub 仓库 = 独立 Vercel 部署。

脚手架命令 CLI

使用 npm run scaffold 从模板创建新的子项目，支持 4 种技术栈模板。

基本用法

scaffold.mjs 命令格式
# 基本格式 $ npm run scaffold -- --name <项目名> --template <模板> --desc <描述> # 短参数格式 $ npm run scaffold -- -n my-project -t nextjs -d "项目描述" # 强制覆盖已有目录 $ npm run scaffold -- -n existing-project -t vanilla --force # 不指定模板时，默认使用 nextjs $ npm run scaffold -- -n my-app -d "我的应用"

参数说明

参数短参数必填说明
--name-n是项目名称（同时作为目录名）
--template-t否模板类型，默认 nextjs
--desc-d否项目描述
--force-f否覆盖已有目录

模板详解

Next.js 14 模板 nextjs

适合 React 全栈应用。

适合 Vue 3 单页应用。

纯 HTML + CSS + JS，适合轻量级静态页面。

templates/vanilla/ ├── index.html # 页面结构 ├── style.css # 样式 ├── app.js # 脚本 ├── vercel.json └── CLAUDE.md

Node.js Express 模板 node-service

Express 后端服务，Vercel Serverless 部署。

templates/node-service/ ├── src/index.js # Express 服务入口 ├── package.json ├── vercel.json └── CLAUDE.md

5. 组装 + 写入
Frontmatter + 正文 → content/blogs/

转换规则

输入类型规则示例

常见问题

API Key 在哪里配置？ ▼ 
export ANTHROPIC_API_KEY=sk-ant-xxx

写入 ~/.zshrc 永久生效，或临时使用 ANTHROPIC_API_KEY=xxx npm run blog:create -- "标题"

工作区不干净时怎么办？ ▼ 
# 提交当前变更
git add -A && git commit -m "wip: save current progress"

# 或暂存
git stash
npm run blog:create -- "标题"
git stash pop
中文 Slug 不准确怎么办？ ▼
  1. 在 scripts/lib/slug.mjs 的 PY_MAP 中添加映射
  2. 或在 frontmatter 中手动指定 slug: my-custom-slug
Push 失败后如何手动推送？ ▼ 
git push
# 或
git pull --rebase && git push
如何添加新的模板类型？ ▼
  1. 在 templates/ 下创建新目录
  2. 放入模板文件，使用 {{project-name}} 等占位变量
  3. 在 scaffold.mjs 的 VALID_TEMPLATES 和 meta 中添加映射
